# Reference 文档规范

Reference 说明公开接口是什么、能完成什么，以及使用时需要遵守的约定。以下各节结合对应模板说明写法；模板中的 `type`、`function`、`arg1` 等是示意名称，使用时替换为实际接口。

## 通用规则

### 说明与措辞

- 开头先补充高层视角，说明接口在对局中代表什么或完成什么。例如执行器记录牌桌以外的状态，可以用对局阶段、结算进度、正在发生的事件解释；不要用执行位置或栈布局代替这层说明。
- 列表中的摘要按对象种类区分：函数和成员函数写“做什么”；类、类型别名、概念、常量、枚举类型、枚举项、成员类型及成员对象写“是什么”。例如 `random_fn` 是“随机函数视图”，`frame_stack` 是“帧栈”，`step` 是“推进至下一执行现场”。参数和返回值同样说明其含义，不能只写一个用途动作。
- 声明、成员表和成员页已经能体现的具体细节，不在开头重复展开。类页不逐项介绍成员调用，也不插入无关类型的用法。内部布局、算法和实现状态不写成公开契约。随机值与游戏效果的对应、调用次序等用户可观察规则须明确说明，不能因实现采用某种算法而省略这些规则。
- 正文提及相关公开接口时链接其页面。参阅只收录紧密相关的接口；类型与辅助函数可以相互参阅，不重复列出父级导航。尚未建立的页面可以先使用预定链接，不为链接专门创建空页。

### 页面要素

主题页通常按“类”“类型别名”“常量”“函数”“枚举”“概念”等 C++ 实体种类分栏，每栏内还可按用途分小栏。也可以采用其他逻辑分组，但同一栏必须是同一种 C++ 实体；参考入口页不受此限制。栏目名称直接使用“类”“函数”等，不加“辅助”或“自由”前缀。

执行主题中的指令和事件各设独立栏目，用带链接的栏目标题指向总表，栏下只写一句说明。

API 页依次给出上级导航、完整限定名标题、公开头文件、声明和概念说明，再按对应模板安排栏目。导航末尾以粗体写当前页名称，不给当前页加链接。

声明保留实际的模板参数、约束、默认参数、限定符和 `noexcept`，不包含函数体或私有成员。约束使用内部辅助类型时，以说明性注释替代内部名字，并在正文说明等价的公开使用条件；推导返回类型保留 `auto`，由返回值说明公开语义。不能把函数体中的使用要求改写成声明中不存在的 `requires`。声明后可以紧接其中出现的相关类型和常量链接。

表格中的标识符用代码格式。索引、模板参数、参数、异常和参阅使用两列无标题表；成员对象使用“名称、类型、说明”三列表头。只有函数条目用动作概括含义，不能将这一写法套到其他条目上。

可选栏目没有内容就删除，不保留空表或占位说明；函数和成员函数的“返回值”是例外，无返回值仍写 `(无)`。不设“调用条件”栏目，必要条件写在开头或“注意”中。

### 示例

每页最多一个 `## 示例` 栏目。有示例时，其中放一个完整的 `cpp` 程序，随后写一行“输出”，再放一个 `text` 预期输出块。多个用法写在同一个程序里。示例按需保留；应实际展示本页接口，不能用无关的固定输出或类型检查充数。

- 示例代码只存在于 Markdown，不另存一份 `.cpp`。只使用公开接口；定义源和效果程序只能组合核心给定的指令。
- 使用完整的 `int main()`，放在示例最后；结尾可以省略 `return 0;`，生成器会在构建产物中补入。
- 所需的无条件 `#include` 放在开头，标准库头在前，本库头在后，中间留空行。正文不使用宏定义、条件编译等预处理指令；辅助声明应能放入独立命名空间。
- 类型等名称显式写出 `givm::`，标准库名称保留 `std::`；可通过实参依赖查找（ADL）找到的本库非成员函数调用优先省略命名空间限定，遇到名称遮蔽或歧义时再显式限定。API 页标题仍使用完整限定名。非空初始化列表内留空格。中文示例优先使用中文注释与带标签的输出，通常使用 `std::println`。
- 先让代码与输出说明用途，仍有必要时加简短注释，最后才考虑在代码块前补少量背景。不要给每个示例加重复引言。
- 输出必须可重复，不打印未固定的随机结果、地址或耗时。优先展示有语义的结果，不随意打印枚举的底层整数。
- 使用 `std::cout` 或普通 `std::print`、`std::println` 输出，保持标准流默认同步，不自行重定向或关闭标准流。输出的空白及末尾换行也参与检查。

修改示例后，构建 `givm_examples` 并运行带 `example` 标签的测试，确认代码可运行且输出与文档相符。生成与验证方式见[示例测试工具](notes/example_tests.md)。

主题和机制说明无需套用下面的 API 模板，但同样遵守分栏、措辞和单个示例的要求。

## 函数

采用[函数模板](reference_templates/function.md)。开头说明函数做什么；同名重载通常合并，以编号对应声明和不同的语义。

栏目顺序为模板参数、参数、返回值、异常、注意、示例、参阅。

- **模板参数**：模板函数保留，非模板函数删除；始终在“参数”之前。说明各参数是什么，以及必要的要求。缩写模板或显式对象形参中的 `auto` 说明对应的推导类型，不虚构声明中不存在的模板参数名。
- **参数**：有参数时保留，说明含义、单位、取值范围和必要限制；无参数时删除。
- **返回值**：必须保留，说明返回对象或数值的含义；无返回值写 `(无)`。
- **异常**：存在需要说明的异常行为时保留，写明抛出条件，不列无关异常。
- **注意**：按需说明前提、易误用之处及相关语义，避免重复开头。
- **示例、参阅**：按通用规则取舍。

## 常量

采用[常量模板](reference_templates/constant.md)。说明常量是什么、值的含义，以及必要的单位或限制；索引中也使用名词性说明，例如“选择结果可表示的位置数量上限”。

常量模板保留“模板参数”，普通常量删除该节。注意、示例和参阅按需保留。普通常量不设函数的参数、返回值和异常栏目；可调用常量仍以对象本身作名词性说明，可以另设“调用方式”说明调用参数、结果和异常，或链接相应调用运算符页。

## 枚举

采用[枚举模板](reference_templates/enum.md)。开头说明枚举表示哪一类概念，“枚举值”表列出全部公开枚举项及其含义，不将枚举项写成函数操作。

注意、示例和参阅按需保留。与枚举配套的类和函数分别使用相应页面模板，在参阅中建立联系，不混入枚举值表。

## 类

采用[类模板](reference_templates/class.md)，也适用于结构体和类模板。开头说明对象是什么；如 `draw_cards` 是抽牌指令，`executor::step` 才是推进执行的操作。指令的内部执行函数不列入公开成员表。

- **模板参数**：类模板保留，普通类删除。
- **成员类型、成员对象**：只列实际公开的成员；摘要分别说明类型和对象是什么。成员对象同时给出类型。
- **成员函数**：摘要说明操作，链接对应成员页。函数较少或没有清晰分类时使用一张表；分组可选，不为套模板勉强分类。
- **构造、赋值和析构**：按实际使用需要列出。通常具有值语义的类型无需单列赋值运算符和析构函数，有特殊语义时再说明。
- **非成员函数**：存在与该类紧密配合的非成员操作时保留，仍按函数写法描述。
- **注意、示例、参阅**：按通用规则取舍，不在类页重复成员页的完整说明和配合示例。

## 成员函数

采用[成员函数模板](reference_templates/member_function.md)。构造函数、析构函数、赋值、转换函数和其他运算符也使用此模板。

与函数页相同，说明它做什么，按模板参数、参数、返回值、异常、注意、示例、参阅的顺序组织。无参数时删除参数节；无返回值时仍保留返回值节并写 `(无)`，包括构造函数和析构函数。

显式对象形参按声明中的名称说明，必要时区分只读与可修改对象的行为或返回类型。同名重载通常合并，不为每一种限定符重复整页。

## 类型别名

采用[类型别名模板](reference_templates/type_alias.md)。说明别名所表示的类型及语义，列表中同样回答“是什么”。别名模板保留模板参数说明，普通别名删除该节；注意、示例和参阅按需保留，不设置函数的参数或返回值栏目。

公开的概念及其他没有专用模板的项目可自由组织，仍应说明它所表达的条件或对象；概念不是运行时执行检查的函数。
