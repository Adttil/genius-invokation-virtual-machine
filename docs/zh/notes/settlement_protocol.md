# 响应返回、分段与延迟程序

第一步重构统一程序调用和后续工作的存储协议。公开接口见 [`return_response`](../reference/definition/commands/return_response.md)、[`end_segment`](../reference/definition/commands/end_segment.md)、[`settle`](../reference/definition/commands/settle.md) 与 [`defer_program`](../reference/definition/commands/defer_program.md)。

## 已接通的调用协议

`handle_context<TEntity, Category>` 持有响应实体；`entity()` 取得该视图，`table()` 从它取得所属牌桌。定义源的 `handle` 接收定义数据、事件、上下文及末尾的 `std::uint32_t` 编号。首轮编号为 0，后续编号来自程序的 `return_response`；普通响应完成当前程序和后续结算后，才再次调用同一实体对原事件的 `handle`。

显式分段在命令位置保存当前边界，不立即处理普通后续工作，也不要求预先统计段数。`settle` 封闭当前末段并完成所属独立域的全部后续结算，再从新空段继续原程序；根程序和普通独立程序均可多次使用。普通和预览效果在返回前执行编译器写入的尾部结算，再退出自身域、恢复外层本方；缺省返回仍补 `return_response::null`。延迟执行复用相同效果和收尾，不要求调用者补结算。即时响应共享外层当前段，返回时不封口，不能执行 `end_segment` 或 `settle`。

预览响应不接收编号，每次报价只调用一次，提交的程序和参数仍按既有报价协议缓存；实际执行时忽略返回编号。延迟程序也忽略自己的返回编号，不改写父响应的继续编号。

尾部结算、退出效果域和恢复本方编译在普通与预览效果自身，调用点仅编译继续遍历响应者的入口。每次调用的 `response_return` 保存返回位置、本方及结果槽，返回编号在结算期间仍留在本次帧内；完成指令退出本次域、弹出调用帧，按具体事件及实体类型更新广播或单播进度，再恢复领域命令续点。费用回放与延迟程序的完成指令忽略编号。独立域的建立与退出由模板参数选择，内联响应直接进入完成指令；返回帧不保存 `phase`、`independent` 或其他运行期阶段分派信息。定义库不再为这些路径预留全局特殊位置，根程序入口不依赖事件列表。

广播和单播均按调用点选择目标，事件类型不绑定投递方式、目标集合或顺序。默认广播告知实体与历史摘要，默认单播只告知指定实体；领域逻辑可自行组合。响应编号及遍历游标保存在调用工作帧上，不转移到 executor 成员或其他全局状态。

## 记录与输入的归属

执行栈继续保存正常消费的命令输入、调用返回及命令工作帧。记录使用三个具名 `frame_stack`：`damage_events_` 保存伤害记录，`hand_entry_events_` 保存入手记录，`mixed_events_` 保存混合记录及段信息。

每个独立调用在三个栈中各建立一个顶层域帧。伤害和入手域帧只有尾部 `substack_t`，混合域帧为 `frame<event_domain, substack_t>`。各类记录分别追加到当前域的子栈中。域头保存最后一个段结束标记的位置 `last_boundary`，未产生边界时为空；不再保存另两个栈的回收位置。子调用在三个栈中都位于整个父域帧之后：

```text
执行栈：领域调用现场及续点 | 本次程序返回 | 尚未消费的输入 | 当前命令及后处理工作帧
伤害栈：[父域伤害记录 | 子栈尾部] [子域伤害记录 | 子栈尾部]
入手栈：[父域入手记录 | 子栈尾部] [子域入手记录 | 子栈尾部]
混合栈：[父域头 | 父域混合记录 | 子栈尾部]
        [子域头 | 子域混合记录 | 子栈尾部]
```

当前独立域直接由三个栈顶取得，各自范围由子栈长度推导；不在执行上下文中保存当前域的主栈偏移，也不在调用返回帧中保存记录范围副本。子域结算完成后，弹出三个完整域帧，父域自然重新成为栈顶。清空当前域则先弹出三个域帧，再原地创建空域，利用已有容量。根流程使用相同的域帧，不单独保存根范围；显式 `settle` 后保留重建的空域供后续命令使用。

小型域头 `event_domain` 定义在 `executor.hpp` 的 `givm::detail` 中，位于 `execution_context` 之前。`reset_event_queues` 在类内完整定义，启动时直接清空三个记录栈并建立空根域，无需另设 cpp 定义。

结算函数集中在私有 `src/executor/settlement.hpp`，按依赖顺序首次出现即完整定义；非模板自由函数使用 `inline` 或 `constexpr`，不保留单独的函数前置声明，也不把原来的匿名命名空间直接搬进头文件。`settlement.cpp` 随之移除。公开执行头不反向包含这个私有实现头。

不能为了分离小函数的声明与定义而随意将实现搬入 cpp。若把函数放在一起确有依赖或组织上的困难，应先报告具体难点并讨论，而不是自行绕开约束。

立即响应沿用当前域，不建立独立记录范围。效果类别是类型信息，立即效果的分段与结算在所有构建的编译阶段被拒绝；不再需要域头或调用帧保存 Debug 响应模式。通用执行上下文只拥有存储和执行位置，段范围与结算规则由内部实现解释。

## 段边界与后处理

段结束标记完整保存本段的四个边界：伤害起点和终点、入手起点和终点。它不依赖前一标记才能恢复本段范围。域头的 `last_boundary` 使用混合栈内的绝对字节偏移直接定位最新标记，不建立标记链，也不逐条扫描混合记录来寻找当前段。

有边界时，当前段的伤害与入手起点取最新标记的两个终点；没有边界时取对应栈的当前域子栈起点。当前段的混合内容从最新标记之后开始，没有标记时从本域子栈开头开始。因此不再另外缓存一组当前段起点，也不预分配段描述数组。

封口工作完成之前，即时响应仍可向当前域追加记录；全部封口工作完成后才写入段结束标记。开始按先进先出顺序处理一个域时，其混合记录序列冻结，处理期间新产生的记录进入独立子域。子域及其派生结算全部完成后，才继续父域的下一项。

主执行栈上的后处理进度只保留遍历游标 `cursor`、当前记录位置 `current` 和恢复位置 `resume`。混合范围从当前域的子栈取得，不重复保存范围尾部或域定位信息。混合记录自身的处理入口和字节长度负责调度及前进；段结束记录负责关联另外两个记录栈的范围。暂停、扩容和复制时保存偏移，恢复后重新取得帧及记录引用；恢复点仍由已编译的指令位置表示。

每个结算调用点编译六条局部指令，分别负责封段、开始遍历、恢复通知、完成响应、接收出战选择和应用选择。开始结算把完成后的续点保存在 `settlement_progress::resume` 中，并定位到遍历指令。遍历指令调用延迟程序时，返回位置就是其相邻指令；延迟效果的尾部结算使用效果自身编译出的遍历指令，另压子结算工作帧，完成后退出子域并回到父工作帧。嵌套层次由正常栈帧表达，不增加阶段字段或结算驱动位置副本。

## 延迟输入

延迟命令是混合记录的实际生产者。`defer_invoke(entry, inputs...)` 返回拥有入口及参数的 `defer_program_input`；参数可以包含变长数组和嵌套延迟输入。`defer_program{}` 整体消费这个动态输入，固定形式 `defer_program{fixed_defer_invoke(...)}` 则在编译时检查并复制完整入口和参数，不占响应输入位置。固定打包对象保留校验描述至编译，描述不写入程序；编译器的输入要求只有 Debug 才保留至运行期。不存在固定入口与动态载荷混合的第三种模式。

登记命令把已经打包的参数复制到记录的自有载荷，动态形式正常消费当前输入；处理记录时再复制回执行栈，进入与普通调用相同的程序。接受这两次复制，不为主执行栈引入被保留的输入块或独立输入游标。

动态延迟输入使用真正的 `frame<normal_effect, substack_t>`，入口后的子栈保存目标程序的完整输入序列。直接放在主执行栈时，这个参数子栈的 view 深度为 1；放在行动费用缓存子栈中时深度为 2。缓存回放复制相同的帧字节到主栈后，按当前位置取得深度为 1 的 view。深度只属于 view 类型，序列字节不保存深度，消费时按完整输入帧弹出。

通用 `pack_inputs` 准备拥有型 `program_inputs`，`concat_inputs` 按执行顺序合并片段，供脚本适配器组合异构输入。普通 C++ `invoke` 仍直接接收各命令的专用输入对象。Debug 描述与实际执行字节分开保存，复制和合并同时保留诊断关系；固定延迟参数在编译时检查，动态提交在 `invoke` 写入前检查。

## 第一提交的领域边界

本步提供记录范围、段边界与处理入口，但旧伤害、治疗、入手等命令尚未整体改为向记录区发布领域通知。它们仍使用既有领域结算时序；不能据此宣称伤害通知已经统一延后，或濒死与入手筛选已经按最终分段算法执行。

伤害和入手记录的范围在本步没有领域生产者。下一步整体迁移对应命令后，再接通段封口时的领域处理和通知分类。现有命令页的领域行为不因本次接口迁移而先行改写。
