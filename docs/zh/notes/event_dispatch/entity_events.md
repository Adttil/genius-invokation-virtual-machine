# 初始化、击倒与实体身份

这里保留初始化同步完成的取舍、击倒后的输入时机，以及离场身份和计数器的规则边界。成员声明见[事件 reference](../../reference/definition/events.md)。

## 初始化刻意同步完成

角色初始状态只涉及角色自己的编译后定义，通过空参数类型的 [`character_initial_state`](../../reference/definition/queries/character_initial_state.md) 提供。结果在编译定义库时求出并保存，初始化时直接写入角色。

初始化不再借用响应接口，也不接受牌桌、随机源或后续效果入口。这个选择同时适用于单个角色入场和已装入牌桌的角色批量初始化；需要依赖当前对局状态的额外效果应由相应事件和命令表达。

## 击倒与延迟出战选择

防止击倒或复活的效果应在真正写入击倒状态前介入；后续响应能够观察到先前响应已经阻止击倒。效果自身的消耗通过响应程序完成。伤害后再进入击倒处理的时机见[伤害与元素反应](damage_and_element_events.md#伤害后的击倒处理)。

原设计明确选择延迟请求替补出战：出战角色被击倒不会立即使系统等待输入，真正需要出战角色的后续指令才请求选择。当前完整击倒、复活和延迟选择流程尚未接入，`begin_action` 仍要求已有出战角色；后续实现需要落实这项分工。

## 离场前后与历史身份

离场前可以读取实体定义和状态，并定点通知实体自身；离场后的 ID 只记录“离场的是谁”，不能再当作存活实体访问。若需要实体自身执行离场效果，负责离场的领域操作应在失效前通知或提前安排。

这项边界也适用于弃牌、打牌完成和调和完成所携带的原牌 ID。通知中保留身份，不意味着框架保存了可继续访问的旧实体。通用离场与弃牌的领域流程尚需补全，不能在实现时丢掉这一先后要求。

## 完整计数器不等于单一剩余次数

带计数实体的 `count` 是完整的 `std::uint32_t`；定义可以自行解释其中的位布局。`entity_count_changed` 记录替换前后的完整值，不能把“次数或层数”的常见用途收窄成只允许单一计数。

零值也不自动表示离场。定义可以按自己的规则，在零值或其他条件下安排离场效果；框架不能统一把 `count == 0` 当作自动销毁条件。不同领域指令对计数的解释和通知责任须分别确定：例如现有 `absorb_damage_by_count` 将它作为可消耗次数，直接减少计数，不自动产生 `entity_count_changed` 或安排离场。
