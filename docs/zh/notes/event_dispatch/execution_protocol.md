# 指令、重入与调用现场

这里记录 command 编译和广播推进器共同依赖的内部约束。公开观察与输入见[执行观察与输入](../execution_observation.md)。

## 输入与完整消费

command 的输入由编译时的具体命令值确定，不依赖外层事件。选择固定参数的命令不消费响应输入；其中相对玩家由 `table.state().self_player` 解析，响应程序执行期间对应响应者所属玩家，具体实体身份仍须显式输入。消费参数的命令读取栈顶的初始输入，完整结束时消费该输入和临时工作帧，保留后续命令的输入。

响应提交时全部输入已经确定。调用方预先在输入下方以 `response_return` 保存外层本方与返回位置，输入按命令执行次序反向排列；命令消耗输入之后，下一个输入自然成为栈顶。程序末尾读取返回记录、恢复外层本方并跳转，不弹出它；调用方完成整段结算后自行清理。一次广播的各个响应程序复用同一返回记录，嵌套广播则建立并清理自己的记录。没有本方用 `player_id{ 2 }` 表示，不以行动玩家回退；根流程需要相对效果时由外层显式初始化有效本方。

每次 execute 调用同步完成，不保存尚未返回的 C++ 调用。进入终局时旧现场被逻辑废弃，是无需逐帧清理的例外。

## 输入快照与实际执行

handler 提交的是一次响应计算出的输入快照。普通响应随后立即进入程序，但程序中的前序命令和嵌套响应仍可能改变 table；后序命令不会重新向 handler 取值。命令输入应在实际执行时满足前提，输入最初计算时有效不代表之后始终有效。

状态绝对赋值使用提交时的目标值，`modify_*_state` 则把已提交的有符号增量应用于执行时的当前状态，并逐字段饱和到定义上限范围。两者都先写入状态再通知自身；召唤物次数耗尽时直接删除并广播离场，不再发送自身状态变化通知。

普通即时响应需要消耗资源时，推荐先执行消耗，再进入可能重入的其他效果，使后续响应看到已经扣除的层数或次数。此建议不限制所有 table 派生参数的消费位置；响应时快照可以按效果需要延后使用。费用缓存跨越报价与提交，且前序缓存程序也可能修改目标，必须单独保证[实际执行时的输入前提](payment_commit.md#缓存输入的快照与执行前提)。

## 重入时必须保留的现场

固定操作数保存在不可变字节流中；事件、输入、循环游标和运行数据保存在栈中，持久状态保存在 table。恢复点由执行位置直接指向 execute 函数，不按额外 stage 再次分派。

暂停或进入子程序前，execute 必须把执行位置与栈调整为恢复时所期望的状态，不能依赖本次函数的局部变量继续存在。广播恢复到下一响应者，支付恢复到下一缓存调用。

## invoke 与借用

handler 通过 `return context.invoke(...)` 写入输入并返回入口，不在上下文中暂存入口。调用可能扩容，因此逐项传入时先按值取得全部初始事件，再写入调用输入。整段字节提交则要求源字节在整个调用期间有效，不能借用因本次调用而移动的现场。输入中的引用型成员不能指向之后会失效的事件。

广播准备时在广播帧尾部保存恢复位置；推进器在每次调用前推进响应游标，调用后不再读取可能失效的旧事件引用。下一次恢复重新定位。行动 view 可以按栈位置重新定位，其成员取得的具体引用不因此获得稳定地址。

`program_invoker` 与 `handle_context` 同在 `handle_context.hpp`，仍是两个类型。调用对象仅保存栈引用；各重载写入输入后原样返回入口，不保存入口、返回位置或行动缓存描述。当前公开响应接收具体 `handle_context&`，以 `invoke(entry, ...)` 和 `invoke(substack_t{}, entry, ...)` 的重载在编译期决定写入主栈还是尾部子栈，不保存运行期模式字段。返回位置由调用方负责准备和清理；费用报价只收集输入，稍后由行动流程安排执行。单实体 `card_effect`、`skill_effect` 调用也由各自流程准备返回位置并在效果结束时清理。

## 准备技能与切换取消

准备技能在 `before_action` 完成后分流，未建立行动候选及费用缓存。选中的 `prepared_skill_effect` 与 `response_return` 保留在栈上；附件先离场并完成通知，再直接调用该附件的效果。传给 handler 的事件使用局部副本，调用后以预存字节偏移写回最终速度，避免 `invoke` 扩容后读取旧帧引用。恢复点分别对应离场通知的响应返回与准备效果的程序返回；无需额外的运行阶段字段。

主动切换、切换命令和超载使用 `set_active_character.hpp` 中相同的实际切换处理。仅当原角色存在准备附件时保留离场 ID 列表、游标、切换事件与通知恢复位置；先全部标记离场，再依次处理通知。没有准备附件时直接进入原有切人广播，不经过新增的离场续点。观察模式先保存切换事件，恢复时才执行实际切换，并在清理完成后建立切人响应者列表。

## 费用缓存

报价只在行动帧尾部子栈追加参数块，行动实现自行根据响应前后的栈增量，在三个数组中分别记录返回入口及参数块的相对位置和长度。确认行动时在整个行动帧上方压入独立的返回位置帧，全部缓存程序复用它；此时缓存不再追加。回放每项前先为该项输入预留必要容量，再按相对位置重新取得缓存字节 span，并通过普通 `invoke` 提交；执行完成后继续处理下一个缓存项。全部支付效果执行完后先弹出返回位置，再开始实际支付。未选候选的参数随行动帧一并释放。

这里的输入块复制不要求逐个事件重新查询，也不需要重排整个缓存。参数块使用相对位置，执行器复制或栈扩容不会改变记录的含义。

## 检查边界

输入数量、类型、顺序或原始字节段须与入口匹配。debug 模式只保存每个入口要求的总输入字节数，并在所有 `invoke` 重载写入前比较总长，不符时抛出 `std::invalid_argument`。不保存类型表，不要求动态源提供类型元信息，同长度错误类型或顺序仍属于未定义行为。Release 不检查总长，违反输入协议属于未定义行为。命令消费输入与清理临时帧的正确性仍须由实现保证。
