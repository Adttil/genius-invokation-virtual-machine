# 伤害组与元素反应的责任边界

伤害组先确定所有命中的属性、反应及附着，再逐段结算数值与扣血，最后处理超载和完成通知。公开输入见 [damage](../../reference/definition/command_inputs/damage.md)，完整契约见 [deal_damage](../../reference/definition/commands/deal_damage.md)。

## 固定输入数量与范围展开

每个 `deal_damage` 独立结算。固定版本在编译时复制 `fixed_damage` 数组；动态版本消费一个 `deal_damage_input`，其 `damages` 数组在响应时决定长度、invoke 时复制。空数组直接结束命令；固定与动态描述均可表示单个角色、其余角色或全部角色。初始描述数量与后续范围、反应展开出的具体伤害数量无关。

一条原始描述先解析锚点，再广播一次 `damage_preparation`，然后按修饰后的锚点展开范围。范围命中共用来源、元素、标志、基础数值和倍率；每个具体目标仍独立判断反应。默认派生不再经过属性修饰，但保留反应选择、数值计算和完成通知。这个限制既避免重复附魔，也使默认派生层级有界：一次扩散可以产生元素伤害，元素伤害的超导、感电再产生穿透伤害；穿透不再派生反应。不同原始描述以及范围内不同命中仍可各自扩散。

风、岩不会形成保留附着；扩散和结晶要求新输入元素分别是风和岩，不能把旧风、岩附着与后来的其他元素反向配对。默认派生按深度优先顺序插入，先处理子项再回到同层后项，然后进入下一条原始描述。

## 整组准备与逐段数值

准备阶段为每个具体命中保存反应前完整 `reacted_aura`、原始 `reaction` 与最终 `replacement_reaction`，随后推进目标附着并准备派生。范围展开、反应选择和属性修饰中的响应程序都可以暂停；恢复后接着尚未完成的位置处理。全部准备完成后不再增加本组伤害记录。

数值阶段按准备顺序广播 `damage_calculation`，完成加算与倍率后广播 `damage_effect`，再扣血并处理死亡。此时牌桌上的元素附着已经包含整组准备的影响；“对原先附着火元素的目标增伤”必须依据本条记录的 `reacted_aura`。例如当前这次火伤刚附上火，不应使本次原附着条件成立。数值、抵挡、扣血及默认反应实体生成仍逐段进行，因此前段生成的领域可以影响后段数值。

准备与数值阶段都不是牌桌快照。响应产生的独立命令即时完成自己的流程，再恢复外组；各阶段读取当前状态。若某目标在数值阶段轮到它前已死亡，跳过其本体数值和完成通知，但保留它在准备阶段已经产生的其他目标派生。数值或抵挡响应中的嵌套伤害也可能击倒当前目标，恢复后需同样跳过余下本体处理，避免重复濒死、扣血与通知。

## 反应选择与默认效果

有反应才广播 `elemental_reaction_will_occur`。其 `reaction`、`reacted_aura` 和 `incoming_element` 只读，`replacement_reaction` 可写；后写覆盖前写，空值恢复默认效果。非空标签取消默认加伤、派生、实体生成与超载切换，但不取消附着消耗和原反应身份。准备阶段确定后不再重算本条反应。

标签不自动执行程序。定义源在已有数值或完成事件中读取标签实现替代效果；另行执行的 `deal_damage` 是独立组。`apply_element` 独立处理附着、反应选择、默认实体和超载，不产生伤害加成或反应派生伤害。

默认超导、感电加伤 1；扩散产生相应元素伤害。激化、燃烧、绽放各自加伤 1，并在当前段扣血及终局判定之后，向反应目标的对方生成所选默认实体。冻结加伤 1，在相同边界向仍存活目标施加默认冻结。生成沿用状态上限、免控、数量限制及同定义重复处理规则；重复响应产生的程序执行完毕后才继续下一段。

## 死亡、超载与完成通知

扣血至零后立即广播 `character_will_be_defeated`，此时角色附属和充能仍保留。响应结束后重新读取生命：已恢复则继续；仍为零先判定终局，若对局继续才清除附属、充能和元素附着。准备阶段已经推进的附着不会在数值阶段重新写回，因此清理不会被后来的已准备伤害撤销。终局立即停止剩余处理，不回退准备阶段已经产生的影响。

默认超载加伤 2。准备阶段第一次遇到“未替代且目标当时出战”的超载时记录玩家。整组数值结束后，以该玩家当时的出战位置寻找下一个存活角色，受当前免控保护或没有其他可切角色时不切换。发生切换时先完成切人观察及通知，再进入各次反应后和伤害后通知。

完成通知直到本组数值全部处理完毕后才逐项广播，此时才调用响应函数，不能提前调用并缓存入口。每个实际处理过的命中先通知反应完成，再通知伤害完成；此前死亡而跳过的本体不发送这两类完成通知，其其他目标派生仍独立完成。每个通知开始时重新采样响应者，所以死亡删除的附属不会再响应。

观察模式在每次非零最终伤害扣血后暂停，随后恢复死亡与默认实体处理；附着早已在准备阶段推进。原组、嵌套组各自独立保存进度，任何一层终局都立即停止全局执行。

## 连续记录与恢复点

组帧由固定头部和一个尾部子栈组成。准备阶段向子栈顺序追加对齐的记录，每条保存 `damage_calculation` 及是否实际结算的 `applied` 标记；不再维护待处理链、完成链或每条记录的下一项偏移。数值与完成阶段复用一个游标顺序访问这段记录，终止范围在准备结束时固定。

头部保留原始描述的共同属性、原始范围与扩散范围的恢复游标、扩散父记录索引、输入数量和当前输入位置、记录总量、当前处理位置、指令位置、选择范围及超载玩家标记。原始范围和扩散可能跨响应程序暂停，需持久保存游标；穿透派生没有属性或反应广播，可同步追加，不另存一层游标。默认派生不再附魔以及风岩规则消除了任意深派生，因此无需通用递归栈或持久链表。

准备期间允许子栈扩容；跨扩容只保留索引，重新取得帧与记录引用。数值与完成期间记录不再增加，使用同一段连续数据。实体生成、重复附属、濒死和切人仍使用对应命令的可恢复流程；通用执行上下文不增加游戏机制字段。

opcode 仅为响应程序返回、输入或观察暂停所需的恢复点拆分；能够直接完成的相邻步骤在当前调用中继续。固定与动态描述在编译时选择读取方式，不在每条记录上重复分派。恢复数值与抵挡响应后检查当前目标是否已被嵌套程序击倒，是维持结算正确性的状态检查，不是对外输入合法性检查。

## 控制与回合开始解除

控制和免控分别由附属定义的 `control`、`control_immunity` 标签表示。定义库查询遍历角色当前有效附属，不维护角色或玩家计数器；直接死亡清理、实体删除和 `clean_up()` 因此不需要补发通知来修复缓存。已有控制不会因后来获得免控而解除。

施加控制的 `attach` 在重复施加分支前检查免控，`add_attachment` 在首次添加及装备替换响应恢复后检查免控。非主动切人命令与超载组末切人检查当时出战角色的免控，主动选择切人使用独立路径。控制状态供上层技能选择与卡牌目标查询检查，执行器不自动校验技能提交。

冻结在数值阶段对自己的物理、火伤害饱和加 2，然后尾调用移除自身，先于减伤和护盾。未破除的冻结响应 `round_started` 规则事件解除，结束阶段不会统一移除冻结；期间新产生的冻结也保留到后续回合开始通知。根流程自动递增回合数、检查上限并清空骰子。回合程序先执行 `start_dice_roll_phase`，再显式执行只负责广播的 `start_round`；同名观察现场由自动推进产生，仍位于回合数递增之后、上限检查之前。不为冻结另设回合结束广播或通用执行上下文字段。

## 治疗完成量

治疗完成通知 `healed` 记录实际恢复的生命值。`heal` 对每个目标先广播可修改数额的 `healing`，再将生命恢复到上限以内。范围治疗完成全部目标的计算与加血后，才按目标顺序广播实际恢复量；满血时也广播数额为零的完成通知。动态输入使用 `heal_input`，可选择精确角色或带范围的相对目标。`increase_max_health` 先增加上限，再恢复相同数量生命，只发送 `healed` 通知。
