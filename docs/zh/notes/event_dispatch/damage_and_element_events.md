# 伤害组与元素反应的责任边界

伤害中的反应选择、数值加成、扣血后的击倒与附着、组末超载切人分别承担不同责任。伤害组规定这些处理与完成通知的边界；公开输入见 [damage](../../reference/definition/events/damage.md)，命令契约见 [deal_damage](../../reference/definition/commands/deal_damage.md)。

## 初始输入与实际伤害

每条 `deal_damage` 拥有自己的结算组。固定 `damages` 在编译时复制；动态模式消费 `input_count` 个 `damage`。固定的是入口输入数量，不是最终伤害数量：范围目标按执行时存活角色展开，元素反应还会派生新的伤害。

一条初始描述开始处理时才解析相对目标或展开范围。范围记录具体角色 ID；已死的 ID 跳过，不重定向到下一个角色。反应派生伤害排在引发它的伤害之后、后续原始伤害之前；派生的元素伤害可以继续引发反应。

对局继续时，每段伤害依次完成扣血、击倒、附着与默认反应实体生成，再继续下一段；整组结束后先处理登记的超载切人及其通知，再按实际伤害顺序进行每次 `after_elemental_reaction` 与 `after_damage`。缓存的是完成记录，不能提前调用响应函数而仅缓存返回入口，否则响应读到的牌桌仍不符合这个边界。任一次扣血后的击倒处理都可能提前终局，当前段尚未执行的附着与反应后果、剩余伤害、超载切人及完成通知随即停止。

组内前一次伤害的计算、减伤、扣血、附着及生成的实体都能影响后一次伤害。该设计不把整组伤害计算成同一份牌桌快照，也不将命中同一角色的多个伤害自动相加。相邻 `deal_damage` 以及响应程序中的 `deal_damage` 是独立命令，不自动并入当前组。

## 属性、数值与护盾阶段

每段伤害先广播 `damage_preparation`。来源、具体目标、元素类型与伤害标志可修改，初始数值与倍率只读。倍率来自初始 `damage` 描述，并原样传入后续数值阶段。所有属性修饰结束后，判定反应并完成替代标签选择，才广播 `damage_calculation`；后者只允许修改数值与倍率。因此早入场的冰伤加成能读取晚入场冰附魔的结果；同一实体同时提供两种效果时，应分别响应两个阶段。

`normal_attack`、`elemental_skill`、`elemental_burst` 是独立可组合的每段伤害标志，不自动包含 `skill_damage`。修改这些标志不改变实际使用的技能，`skill_used` 等事件仍保留实际技能身份。此处不把技能定义分类与本段伤害的视为效果合并。

`damage_calculation` 结束后，只在替代标签为空时加入默认反应加伤，再统一应用倍率。`damage_effect` 继续负责扣血前的最终数值修饰，例如减伤和护盾，不并入前面的加算阶段。增伤倍率为何在加算结束后统一应用，见[指令设计备忘](../instructions.md#结算边界)。

## 一次判定与替代标签

反应种类、反应前的完整附着和最终输入元素在属性修饰结束后判定一次。若发生反应，立即广播 `elemental_reaction_will_occur`，其反应信息只读，唯一可写字段是 `replacement_reaction`。响应按既有广播顺序执行，后写无条件覆盖前写；写回空标签则使用默认效果，不增设优先级或首次选择锁定规则。

标签确定后才进入数值计算。`damage_calculation` 公开只读的 `reaction`、`reacted_aura` 与 `replacement_reaction`；即使响应返回的程序改变目标附着，本段也不重新判定。`damage_effect`、`after_damage`、`after_elemental_reaction` 和扣血观察视图沿用原始反应与同一个替代标签。

非空标签取消默认反应加伤、派生伤害、实体生成和超载切人；附着消耗不受替代影响，仍按已保存的反应判定更新。原始反应保持成立，所以按元素反应种类判断的效果和反应后通知都能认可它。没有发生反应时不广播选择事件。

## 默认效果与替代效果

替代标签只描述选定的效果，不自动执行程序。定义源通过已有数值、反应后或伤害后事件读取标签，实现普通响应效果，例如在反应后造成额外伤害。该响应中的 `deal_damage` 是独立嵌套组，不追加进原组。这里不增加替代反应广播或自定义同组伤害追加接口。

`after_elemental_reaction` 位于组内全部扣血、附着、默认反应实体生成和超载切人通知之后；由伤害引发时，它在对应伤害后通知之前。无反应的附着不应仅因为修改了附着就发送反应通知。独立 `apply_element` 也在判定后选择标签，沿用同样的派生伤害、默认生成及组末超载边界，但不产生主目标伤害或主目标反应加伤。

超导、感电和扩散的默认派生伤害由当前组直接处理，不依赖定义源再返回一段伤害程序；派生目标仍在主段扣血与附着处理时采样，不因选择事件提前就提前展开。激化、燃烧、绽放分别产生 1 点默认反应加伤，并在当前段的反应处理中请求生成激化领域、燃烧烈焰、草原核。超载默认加伤为 2，切人延迟至组末。冻结状态生成等未完成的默认反应后果见[源码问题清单](../reference_scope.md)。

## 默认反应实体的生成边界

三类实体均生成在发生反应角色的对方，以 `other_player(target.player_id)` 确定归属；不从伤害来源或执行时的 `active_player` 推断。自身附着引发反应也采用这一规则。定义 ID 取自定义库所选的反应定义，重复生成调用已有实体自己的 `combat_status_regeneration` 或 `resummoning`，沿用状态上限与召唤物容量规则。

替代标签为空时，在当前段扣血、击倒与终局判定之后处理默认生成。附着消耗始终处理，默认派生伤害与实体生成则由标签决定是否执行。生成完成后继续下一段，不另外积累生成请求或扫描整组记录。

引发反应的本段伤害已经完成数值计算与扣血，不会获得本次新生成实体的追溯增伤。之后的同组伤害和伤害后响应另行造成的伤害，可以使用仍在场且满足条件的实体。激化领域只增强对敌方出战角色的雷、草伤害；对后台角色未增伤不能据此判断领域尚未生成。

重复生成响应可以提交程序；该程序完成后才继续下一段伤害。程序中的嵌套伤害是独立组，可产生观察或输入停点；若它结束对局，外组余下的伤害与通知都停止。所有 `after_elemental_reaction` 和 `after_damage` 仍等整组结算完毕后广播，每个通知在开始时分别采样候选响应者。

旧文把 `reacted_aura` 称作“参与反应的旧 aura”，不能据此把它收窄成仅包含被反应消耗的那部分附着；当前语义是反应开始前的完整目标附着快照。

## 超载的组末切换

本段反应判定并完成标签选择后，若原始反应是超载、标签为空且目标当时是其所属玩家的出战角色，就登记该玩家。整个组只登记首次符合条件的超载，后续超载仍各自获得默认加伤，但不再登记切人。

组内所有伤害、附着与默认实体生成结束后，才以该玩家当前出战位置为基准，循环寻找下一个存活角色。原目标后来死亡或被其他效果换下，不取消登记，也不要求仍由原角色出战。唯一存活角色已经出战时无需切换或通知；若切换发生，先完成 `active_character_changed` 观察与广播，再进入本组的反应后和伤害后通知。终局直接结束，尚未进行的切人不再执行。

组头用一个紧凑玩家标记表示玩家 0、玩家 1 或尚未登记，不额外记录角色 ID、节点偏移或每条超载请求；这是本组首次切人资格的缓存。组末直接读取一次即可，无须扫描完成链寻找超载。逐段实体生成继续使用原路径，也不引入组末生成遍历。各命令及嵌套伤害组分别保存自己的登记。

## 扣血后的击倒处理

击倒处理紧接每次扣血，先于该次附着更新、默认实体生成及整组的完成响应；反应判定和标签选择已在扣血前完成。当前尚未接入濒死复活广播：生命降至零时先检查双方存活情况，若判定终局则立即停止，不再清理该角色的 attachment 与充能。只有对局继续时才删除角色全部 attachment、清空充能，再处理元素附着；已经删除的 attachment 不参与后续完成响应。终局也会停止当前段尚未执行的反应后果、剩余伤害、超载切人及所有尚未执行的完成响应。

濒死广播应插入生命降至零的分支，在 attachment 与充能仍保留时执行，使角色自身 attachment 也能提供复活。广播恢复后重新读取生命；若已复活则直接继续，否则立即判定终局。只有对局继续时才删除 attachment、清空充能；终局不承担这些后续清理。这个恢复点属于伤害命令本身，不需要给通用执行上下文增加伤害状态，也不能将清理推迟至伤害后响应。

观察模式的 `health_reduced` 仍紧接扣血，公开读取原始反应与替代标签；恢复后先进入上述击倒处理，再处理元素附着和默认实体生成。当前段的实体在该观察现场尚未生成，但前段生成且仍在场的实体已经可见。超载引发的切人观察位于本组全部伤害处理之后、完成通知之前。终局检查由伤害命令承担，不能要求定义源另接一条通用检查指令，见[指令设计备忘](../instructions.md#结算边界)。何时请求出战选择的规则见[击倒与延迟出战选择](entity_events.md#击倒与延迟出战选择)。

独立命令与组内反应派生伤害遵守相同的扣血后终局边界。例如外组 A、B 已扣血，A 的伤害后响应再执行致死伤害 C；C 扣血后判定终局时，C 自身和外组 B 的伤害后响应都不会再执行。不需要跨层协调最外组收尾或保存额外的嵌套层数。

## 组内存储与续点

每个组拥有一个固定头部和尾部子栈。第一个伤害记录直接存在头部中，后续记录按实际需要压入子栈；记录之间用相对整栈起点的偏移连接，扩容和执行器复制都不需要修正指针。一条记录先属于待处理链，本次扣血与元素处理完成后复用同一个链接加入完成链，避免同时保存多份事件副本。

伤害处理中的记录保留在对应链首：属性修饰、数值计算、扣血及反应广播期间由待处理链首定位，反应后及伤害后广播期间由完成链首定位，完成相应处理才推进链首。处理反应派生时先将当前记录移入完成链，再把派生记录插入待处理链首；这两个内部步骤之间没有响应调用，不改变伤害或通知顺序。已失效的待处理目标则直接推进链首，不加入完成链。

`prepare_combat_status_generation` 与 `prepare_summoning` 供独立生成命令和逐段反应处理共用：输入按值传入，显式提供响应程序的返回位置；只有重复生成需要响应时才保存该位置。handler 返回空入口时当场清理，返回程序时由调用方进入程序。当前段记录先移入完成链，生成恢复入口弹出返回位置后继续伤害组循环，不重复生成。领域进度与返回位置都保存在原有栈结构内，通用执行上下文无须增加状态。

初始输入数量和指令区位置只初始化一次、会反复读取，仍缓存在组头部。动态输入紧邻组帧下方，读取时从已经取得的组头部地址减去固定布局位移定位，避免另外保存、读取输入边界；位移包含组帧前端的对齐填充。首节点内置方式仍保留，避免常见单伤害再追加一个子帧。优化以执行耗时为先，不能仅因某项信息可推导便移除缓存。

初始描述按游标读取，范围目标展开为具体 ID。反应派生记录插入待处理链的前端，保持派生先于原本后续伤害的顺序。只有当前广播帧弹出、组帧重新位于栈顶时才扩充子栈；指令续点负责在计算、扣血、反应和完成广播之间切换。调用结束时弹出整个组和该命令消费的输入，通用执行上下文与调用协议均不需要伤害专用字段。

命令为属性修饰、反应选择、数值计算、伤害结算、反应后与伤害后广播保留各自的恢复入口；默认实体生成另有重复生成响应的恢复入口。组末超载只为切人广播保留恢复入口，观察模式再增加观察后写入出战角色的恢复入口；普通路径直接调用完成循环，不额外跳转到无条件收尾 opcode。独立 `apply_element` 复用伤害组的处理布局，但其自身附着直接进入反应选择，只有派生伤害才经过伤害属性与数值阶段。准备广播后直接尝试执行；只有进入响应程序时才交还调度，并使用对应 opcode 恢复。切换下一条伤害及遍历完成记录都由局部循环完成，不另设无条件相邻执行的 opcode。

固定参数和动态输入在编译时选择不同的执行函数实例，逐项读取时不再判断输入来自程序还是栈。局部阶段函数用 `std::optional<execution_state>` 区分两种结果：空值表示本阶段已经同步完成、调用方继续循环；有值表示已进入响应程序、观察暂停或终局，应交还调度。阶段之间可以直接调用，但每次伤害完成都会返回循环，不形成随伤害数量增长的 C++ 递归调用链。

## 治疗完成量

治疗完成通知 `healed` 应记录实际恢复的生命值，不能把治疗前提出的数额直接当作最终恢复量。当前治疗事件类型已声明，核心治疗流程尚待补全；这一区分仍是实现应遵守的要求。
