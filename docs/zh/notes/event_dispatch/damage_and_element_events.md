# 伤害、元素反应与段结算的责任边界

每条伤害命令立即完成自己的属性修饰、数值计算、扣血和默认反应效果。多个命令通过显式段收尾和结算点组织共同通知，不再使用命名伤害组。公开输入见 [deal_damage_input](../../reference/definition/command_inputs/deal_damage_input.md)，命令契约见 [deal_damage](../../reference/definition/commands/deal_damage.md)。

## 命中与即时广播

固定命令包含来源、目标范围、基础数值、倍率、类型和标志；动态命令消费一次伤害参数数组，按顺序完成各项。每项在开始时采样目标集合，从原始锚点按循环顺序处理，每个命中独立广播 damage_preparation、damage_calculation、damage_effect，并读取当前牌桌。同段零生命但仍 alive 的角色继续完成伤害计算和反应；普通目标不会自动转移。只有明确的 prioritized 会选择第一名正生命存活角色，不修改出战位置。

属性修饰可以修改来源、目标、类型和标志。数值计算在同一个可修改事件中收集加值与倍率，普通响应结束后再告知所选反应定义；最后统一先加后乘并向上取整一次。抵挡阶段只能修饰最终数值。响应程序属于内联调用，记录进入外层段，不能显式收尾或结算。

普通模式按计算、操作及结算所需流程独立设计，不保存观察快照、不执行观察用复制或恢复步骤。观察模式可以编译不同流程和帧；当前实现在实际非零扣血后暂停，读取最终 damage_effect 数据，恢复后继续反应。after_damage 属于段通知，不能用它还原某次命中的来源或排列。

## 反应定义与附着

基础化学关系用 17 个固定槽位表示：九种元素配对、四种元素扩散及四种元素结晶。每位玩家保存槽位到 reaction_view 定义 ID 的映射。编译接收默认定义名称，调用方事先登记完整依赖闭包；装载牌组按角色顺序应用全局替换，同槽位后面的覆盖前面的，不作强制冲突检查。角色死亡不撤销映射。

反应映射取自反应目标的对方玩家；事件同时保存原始来源，并用 source_player() 表达实际引发玩家。给自己附着引发的反应因此可以使用对方映射，而仍将自己识别为引发来源。派生伤害保留原来源。

reaction_aura 查询先给出默认 new_aura，再广播 elemental_reaction_will_occur，允许普通响应直接改写附着并取消默认后续效果。核心写入最终附着后，才调用所选反应定义。cancel_reaction_bonus 与 cancel_default_effects 分别控制反应加伤和后续效果，两者都不消除反应事实；after_elemental_reaction 始终按记录通知。

默认反应加伤、派生伤害、实体生成和超载均由普通定义与命令表达。单独 apply_element 也执行反应后续效果，扩散等可以产生派生伤害，但没有原始命中的反应加伤。默认超载即时判断目标是否仍为出战角色，寻找其他存活角色并调用非主动切人命令；不为整个段合并成一次超载。

## 段收尾与濒死

伤害队列按目标首次出现顺序追加记录，同段同目标合并最终伤害数值，并对类型、标志及反应槽位取位或。数值饱和累加；每条记录紧邻保存 pending_dying 和 defeated。新增角色和即时响应产生的伤害可继续扩展队列，不预留按初始角色数量计算的容量。

end_segment 和结算调用方的尾部收尾处理 pending_dying。角色生命已经为零但 alive 仍为 true，充能、附着和附属暂保留。character_will_be_defeated 的响应属于内联调用；免于击倒恢复会写入同段治疗记录。处理后仍为零则置 alive=false、清除充能及附着。后续濒死响应可能重新伤害先前救回的角色，收尾会重访其待办记录，也会继续处理响应中新加入的记录。整段濒死尝试全部完成后统一判断双方终局，双方全队击倒按 both_loss 处理；终局成立便不处理普通通知或请求选择。

确认击倒后的附属逐个清理，在 fatal after_damage 之前执行自身离场效果及其完整结算，再进行普通离场广播。after_damage.defeated 保存本段确实发生过的击倒事实，即使混合通知已经令角色复苏也不清除。

## 通知顺序与调用返回

每段先处理混合通知，然后处理收尾时保留的入手记录，接着处理未击倒的伤害记录，最后处理击倒记录。混合区中的延迟程序按变长记录携带动态参数；处理时复制回主栈，并使用与普通响应相同的入口和编译协议。

普通响应建立子结算域。每个响应者先调用 handle 0，执行返回程序及调用方补做的尾部结算，再根据程序返回编号继续同一响应者。下一次 handle 因而能观察上一轮的完整结算结果。原事件、响应者游标和返回编号均保留在栈帧；恢复步骤由调用点编译，不在 instruction.hpp 增加事件专用全局位置，也不添加运行期 phase 或 independent。

伤害、入手及混合记录使用三个有明确名称的队列栈；域和段定位信息放在队列帧上。主执行栈只保存当前操作及恢复进度。子栈深度由类型表达，沿用每层子栈均在顶部才能增长或弹出的规则，不依赖公开 at 或 truncate。

## 入手与离场

入手先建立手牌 ID，超过容量时立即使该手牌无效并记录 overflow。段收尾保留 overflow 或仍在接收方手中的记录；普通失效或转移的入手记录被排除。这个决定在收尾时冻结，处理混合通知时发生的再次离场不影响已经保留的入手通知。

自身离场效果与普通离场通知使用不同事件类型，前者通过 context.entity() 读取自己，不重复携带自身 ID。普通广播候选在自身效果开始前采样，自身效果完成后记录历史摘要，再处理已采样的全场响应者。

## 治疗与切人

normal 治疗要求 alive 且生命非零，经过 healing 修饰。prevent_defeat 恢复 alive 且生命为零的濒死角色；revive 恢复已经死亡角色，两者绕过普通治疗修饰。三者都登记 healed，实际复苏成功在 healed 前登记 character_revived。增加生命上限保留原有直接恢复行为，不进行普通治疗修饰。

每次 settle 在正常派发致命伤害记录时向 settlement_progress 累计 cause_defeated。通知及其派生响应完成后，只有本次确实造成击倒才检查双方当前出战。无自身击倒的子响应不提前处理父域的死亡出战；有自身击倒的子响应会检查双方，可能在父域剩余通知之前请求选择。event_domain 不保存此业务事实，结束时也不额外遍历伤害队列。

双方需要选择时，第一个答案只保存在选择栈帧中；收齐双方答案后，按当前行动方、另一方的顺序逐个切换，并完整处理各自通知，再恢复原调用者。公开 view 可以逐个请求输入，收齐之前不修改牌桌。显式中途 settle 同样完成选择后才继续程序；多条 end_segment 期间不请求选择。
