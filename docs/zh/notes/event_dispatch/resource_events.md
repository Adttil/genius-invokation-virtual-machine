# 资源结算与旧费用存放方案

这里保留资源结算尚需落实的规则，以及旧费用方案与当前行动系统的差别。事件的基本用法和成员见[事件 reference](../../reference/definition/events.md)。

## 广播完成后统一限幅

充能变化的原约定是：响应先调整本次变化量，再由负责充能变化的领域指令在广播结束后统一应用上下限，最后通知实际变化。限幅不由事件对象本身完成，也不要求每个响应者各自裁剪最终充能。

当前核心指令集合尚无旧文所称的 `change_energy`，但“广播后统一限幅”仍是待实现的结算要求。不能仅凭已声明 `changing_energy` 和 `energy_changed` 就认为该流程已完成。

## 被替代的 payment 槽位方案

旧 `calculating_card_payment`、`calculating_skill_payment`、`calculating_switch_payment` 方案把 payment 放入 table：分别使用手牌、技能以及切换目标角色对应的槽位。响应通过 command 修改槽位中的费用、行动速度或 `on_pay`；后一个响应读取前一个响应执行后的最新槽位。

当前主动切人采用 `cost_of_switch` 事件计算费用，把确认行动后才需提交的效果另行保存；当前手牌、技能和角色状态中没有上述 payment/`on_pay` 槽位。保留下来的 `calculating_*_payment` 类型不能当作旧存放方案仍在运行的证据，也不能与现有切人费用流程混用。

费用预览为什么不能立即消耗效果次数、提交为什么只执行选中行动对应的效果，集中在[费用预览与提交](payment_commit.md)。

## 资源事件由领域操作决定

“骰子发生变化”不自动要求每次都广播同一种资源事件。例如投骰阶段和回合开始清空骰子，并不等价于普通增减骰操作。今后补全资源操作时，应分别确定其通知规则，不能从某一条已实现的支付路径推导所有骰子变化的广播要求。
