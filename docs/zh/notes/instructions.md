# 指令设计备忘

本页保留指令设计中的理由、反例和待处理问题。接口见[指令 reference](../reference/instructions.md)，具体实现直接阅读[指令源码](../../../include/givm/executor/instructions)。

核心给定指令集合的限制、一次执行与完整结算的区别，以及 `deal_damage` 后不能直接接 `absorb_damage_by_count` 取得伤害事件 context 的反例，集中在[固定程序设计](fixed_program.md)。这些约定不取决于模板是否已经提供相应静态检查。

## 结算边界

会降低角色生命的领域指令应当负责自身完整结算后的终局检查，不能要求定义源在后面手接一个通用检查指令，否则新增效果容易漏掉检查。`deal_damage` 在伤害后响应全部完成后检查双方是否还有存活角色；未来增加其他降低生命的路径时，也必须明确承担这项责任。这是领域指令的设计要求，不表示其他路径已经实现。

伤害的加算修正先完成，再统一应用倍率，避免响应者先后顺序把“先加再乘”变成“先乘再加”。例如同样是基础值 3、加 1、乘 2，逐响应者直接修改最终值可能得到 8 或 7；将倍率保留到加算结束后统一处理，避免这一差别。

批量抽牌和单方换牌把整批牌区修改放在通知之前，是为了让前一张牌的响应不能改变本批次后续抽到的牌。通知本身仍可以影响后续响应：前一个通知创建的实体可能响应本批次后面的通知。因此“整批牌先确定”不等于“所有通知共用同一份响应者列表”。

## 同时输入的次序

双方开局换牌允许一方提交后立即看到自己的换牌结果，但不在该同步流程中广播 `card_drawn`，以免玩家提交先后改变响应结算顺序。双方选择出战角色则先收齐选择并写入双方结果，再开始通知，使响应不会观察到只有一方完成设置的中间状态。

开局换牌和双方重投还需要避免提交先后改变各玩家得到的随机值，因此预先按玩家分配随机输入。预发对回放和分支的影响集中在[随机输入备忘](random_replay.md)。这些具体安排不构成所有事件都必须采用的广播顺序。

费用预览与确认后提交效果分离，使查看一个候选行动不会提前消耗减费次数，最终只提交选中行动对应的效果。这一分工及旧称“支付后效果”与实际扣款时机的区别，见[固定程序设计](fixed_program.md)。

## 配置取舍

- `start_battle` 在首回合才广播战斗开始，因而可以放在每回合复用的同一段程序中，无需另建首回合专用程序。这不意味着第一回合重复放置该指令也只会通知一次。
- `insert_deck_card` 没有接收初始牌状态的字段，原有理由只是 `card_state` 当前为空，创建时可以采用默认状态。未来增加状态字段时应重新审视初始化参数，不能把“永远不需要配置牌状态”当作已经作出的设计决定。

## 遗留选择协议

旧的 `push_selector` 与 `roll_dice` 把选择对象留给相邻指令消费，属于引入完整领域指令以前的合作方式。当前的换牌、重投等指令各自负责输入与结算，正常结束后恢复进入前的栈形状，不再依靠这个前置生产、后置消费的协议。两个旧头仍在源码中，但不由公共指令头导出。

这组旧头还存在兼容问题：[`push_selector`](../../../include/givm/executor/instructions/push_selector.hpp) 压入选择后调用 `enter_next()`，而当前后者会重置栈顶进度值；旧选择对象没有为这项操作准备相应后缀。不能仅凭文件仍在就认为旧组合可以用于当前执行器；整理遗留代码时应先解决或移除该路径。

[`process_dice_roll_phase`](../../../include/givm/executor/instructions/process_dice_roll_phase.hpp) 仅保留旧名称到 `start_dice_roll_phase` 的别名，没有独立的另一套投骰流程。原记录未提供名称变更之外的额外设计理由。

## 待处理问题

[`begin_action`](../../../include/givm/executor/instructions/begin_action.hpp) 的结束声明分支只排除空请求，随后按行动种类决定是否宣告结束，因此其他非空请求种类也会进入该分支。原约定使用 `do_action + declare_round_end` 表达确认结束；实现接受更宽输入不应被理解为新增公开用法。

计算后候选费用缺少独立读取入口，以及默认元素反应尚未完成的部分，已集中记录在[源码问题清单](reference_scope.md)。费用缓存因此被旧测试直接访问，并不使完整缓存布局成为公开接口。
