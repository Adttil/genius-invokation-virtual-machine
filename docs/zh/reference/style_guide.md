# Reference 写作规范

Reference 说明公开接口的用途、使用方式和语义约定。类、枚举、函数、类型别名、成员函数和常量页从对应的[模板](templates.md)起稿，删除不适用的可选栏目。其他页面自由安排内容和结构，每页至多设置一个“示例”栏目。

## 页面组织

- 入口为 `docs/zh/reference.md`，内容位于 `docs/zh/reference/`。父页与子目录同名，例如 `executor.md`、`executor/executor.md`、`executor/executor/execute_next.md`；不使用 `README.md`。
- 类页索引成员，成员函数各有页面；同名重载通常合并在一页。
- 指令统一放在 `instructions/`，事件放在并列的 `events/`，相关页面互相链接。
- 主题、机制、指南等页面也属于 reference，具体内容自由组织。内部实现及历史设计说明放在 `docs/zh/notes/`。

## 模板使用

模板文件直接展示目标页面的结构。复制整页后替换示意名称和说明，按实际接口调整声明和栏目。

- 页首导航按层级链接上级页面，末尾以粗体写当前页面名称，不给当前页加链接。例如类页为 `[givm](../../reference.md) / [主题](../topic.md) / **type**`，成员页再增加所属类的链接。相对路径以新页面的位置为准。
- 模板中的声明只展示语法结构。非模板接口删除声明中的 `template<...>`、示例中的模板实参和“模板参数”整节；模板接口按实际情况填写类型参数、非类型参数或模板模板参数。
- 类页仅保留实际存在的成员栏目。“成员对象”使用“名称、类型、说明”表；成员函数索引链接独立页面，可按用途分为三级标题下的分组。构造、析构和运算符也使用成员函数页模板。
- 枚举页列出全部公开枚举项并说明其含义。类型别名页说明别名的用途；常量页说明值的含义和读取方式，不使用函数页的“参数”和“返回值”栏目。
- 没有内容的可选栏目直接删除，不保留空表或占位说明。

## API 页结构

这六类 API 页依次放置层级导航、完整限定名标题、公开头文件、声明和说明。类型、枚举、类型别名和常量的开头说明它是什么；函数页和成员函数页说明它做什么，再按需补充用途和使用方式。

声明保留实际的模板参数、约束、默认参数、限定符和 `noexcept`，不展示私有成员或函数体。不要把函数体对实参的要求改写成声明中不存在的 `requires`。

声明代码块后可以紧接相关接口的链接，方便查阅声明中出现的库内类型、常量等；相关页面尚未建立时，可以先链接到预定路径。

同名重载通常合并在一页，以编号对应声明和各自的说明。

函数页和成员函数页按以下顺序组织：

1. **模板参数**：模板接口必有，位于“参数”之前；非模板接口删除。说明参数的含义和类型要求。缩写函数模板与显式对象形参中的 `auto` 也要说明对应的类型推导，例如“`self` 推导的对象类型”，不为其虚构公开模板参数名。
2. **参数**：有参数时保留，说明含义、单位、取值要求等；显式对象形参也按声明中的名称说明。无参数时删除本节。
3. **返回值**：必有；无返回值写“（无）”。
4. **异常**、**注意**：按需保留；必要的使用条件写在开头或“注意”，不设置“调用条件”栏。
5. **示例**：必有，使用完整可运行的程序和对应输出。
6. **参阅**：按需保留，只列出可替代或需紧密配合使用的接口，不重复父级导航。

## 说明与链接

- 正文说明接口的用途、效果和使用约定。共通机制写在机制页，接口页保留相关约束并链接它。
- 成员索引和函数摘要直接说明该成员是什么或做什么，不只重复类型名称。正文提及库内接口时，链接其页面；尚无页面时可以使用指向预定路径的链接，无须为此创建占位页面。
- 参数、模板参数、成员索引、异常和参阅表使用两列无标题表格。成员对象表使用“名称、类型、说明”三列表头。

## 示例写法

六类 API 页均给出一个完整的 `int main()`，包含所需头文件，只使用公开接口。其他页面按需设置示例栏目，至多一个；存在示例时，同样须提供完整程序和对应输出。展示多个用法时，在同一个 `main` 中分段演示。`main` 放在示例最后，结尾可省略 `return 0;`；汇总构建所需的返回语句由[示例生成器](style_guide/examples.md)补入构建产物。示例以展示本页内容的实际用途为主，不展开无关的对局规则。

优先用带标签的输出解释结果，例如 `std::cout << "round: " << round << '\n';`。仍需解释时，添加简短的代码注释；仅当代码和输出不能交代必要背景时，在代码块前补充少量文字。不要给每个示例添加重复的引言。

示例代码后写一行“输出”，接 `text` 代码块。输出须可重复，避免未固定的随机结果、内存地址和运行耗时；枚举通常通过有语义的判断或名称展示，不打印无助于使用的底层整数。

文档代码块是示例源码的唯一来源。示例栏目使用 `## 示例` 标题；生成器读取该节的第一个 `cpp` 代码块及其后的第一个 `text` 输出块，缺少任一代码块时会报错。构建时汇总到一个编译单元，每页对应一个带 `[example]` 标签的 Catch2 测试用例。运行时核对文档输出；不另外维护一份 `.cpp`。具体约定和命令见[示例维护与验证](style_guide/examples.md)。
