# 核心概念

GIVM 把一套游戏规则与使用这套规则进行的各场对局分开。相同角色和卡牌可以同时出现在许多场对局中，但每场对局的生命值、手牌、资源和正在处理的效果各自独立。

## 规则与对局

| | |
| --- | --- |
| [定义](../definition.md) | 角色、卡牌、技能和状态是什么，以及它们如何响应游戏变化 |
| [`card_table`](../table/card_table.md) | 一场对局的牌桌，例如双方角色、手牌、骰子和回合数 |
| [`executor`](../executor/executor.md) | 牌桌以外的对局状态，例如进行到哪个阶段、结算进度和正在发生的事件 |

一套定义可以供多场对局共享。每场对局使用自己的牌桌与执行器，运行时由调用方提供随机源。要重现相同后续，需要同时保持规则、对局状态、外部输入和随机序列一致。

## 定义与实体

定义描述一种游戏对象，实体表示它在某场对局中的一次出现。例如，一张卡牌的定义可以对应双方手中多张独立的牌。实体可以有自己的状态；相同定义不表示它们是同一个实体。

定义 ID 用于查找定义，实体 ID 用于在相应牌桌中定位实体。通过牌桌取得的实体访问对象和只读 view 用于观察、操作实际对局中的对象。具体身份和失效约定见[牌桌](../table.md)中的相关页面。

## 指令与事件

[指令](../instructions.md)描述要执行的游戏操作，例如抽牌、施加伤害或开始一个回合。初始化和回合流程、角色或卡牌产生的后续效果，都可以用指令组合表达。

[事件](../events.md)描述可供响应的游戏变化，例如正在计算伤害或角色已被击倒。定义可以响应事件；需要后续操作时，响应可以选择事先准备的效果。

有些指令可以独立使用，有些只适合某种事件的响应。这个限制由 context 表达：它说明这段效果正在响应什么。

## 外层程序

界面、决策程序或测试驱动负责选择输入并展示结果。执行器推进到需要外层处理的位置时会暂停。外层程序根据对局结果和当前指令，决定是否提交输入、记录观察结果或结束驱动。具体步骤见[驱动与输入](driving.md)。
