# 实体的身份与访问

实体是对局中的具体对象，例如某张手牌、某名角色或某个召唤物。同一个定义可以在不同对局中或同一对局中产生多个实体；定义说明它们是什么，实体保存它们各自的当前状态。

牌桌仅保存实体的定义 ID，不持有定义库。实体的 `definition_id()` 返回其定义身份；需要查询名称或完整定义时，由调用方显式使用配套的 `library[entity.definition_id()]`。定义响应可以将实体的定义 ID 与编译时取得的依赖 ID 比较，无须查询名称或其他定义的响应方法。

## ID 和访问对象

实体 ID 用于在牌桌中定位实体。通过牌桌的 `operator[]` 或玩家、角色的遍历接口得到的实体对象，是访问该实体的入口；复制这个对象仍访问同一个实体，不会复制一份游戏状态。要建立独立的模拟分支，应复制牌桌，并为分支配套保存执行器和随机源状态。

玩家 ID 只有 0 和 1。其他 ID 不表示“当前遍历到的第几项”。尤其是牌库顺序可以改变，而同一张牌的 [`deck_card_id`](deck_card_id.md) 不随换序改变。

## 只读访问

从牌桌取得的对象始终使用相应的 `*_view` 类型，只允许读取实体。玩家、角色、卡牌及其子实体的访问也保持只读。视图不拥有或冻结牌桌；执行器修改实体后，后续读取反映牌桌的当前状态。

## 移除与清理

规则执行可以移除实体。移除后 `is_valid()` 和 `operator bool` 返回 `false`，默认遍历跳过该实体；清理前，原有 ID 仍能用于读取其保留的定义 ID、状态、实体 ID 及所属玩家或父实体。有些遍历接口的 `SkipErased = false` 也可以访问这些尚未清理的已移除实体。

这项读取保证适用于曾存在于对应位置、随后被删除的实体。卡牌在牌库与手牌之间转移时会取得新区域的 ID；原区域的卡牌 ID 和卡牌状态 ID 不保证仍可读取。清理牌桌后，也不能继续使用此前保存的实体 ID。

实体访问对象、状态引用和遍历范围不拥有牌桌。增加或移动同类实体可能使已取得的访问对象和引用失效；即使已删除实体的数据仍然保留，也须通过尚可定位的 ID 重新取得访问对象。`clean_up()` 还可能改变 ID，所以不能跨清理保留这些 ID。不要把 `is_valid()` 当作悬空对象检查：它只适用于仍能安全访问的对象。


## 修改牌桌

通过 [`load_deck()`](table/load_deck.md) 装载牌组，通过执行器执行[命令](../definition/commands.md)推进对局。状态读取接口不提供可修改引用。对局参数在构造牌桌时传入；[`clean_up()`](table/clean_up.md) 由调用方主动发起。
