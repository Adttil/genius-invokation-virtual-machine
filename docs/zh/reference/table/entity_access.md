# 实体的身份与访问

实体是对局中的具体对象，例如某张手牌、某名角色或某个召唤物。同一个定义可以在不同对局中或同一对局中产生多个实体；定义说明它们是什么，实体保存它们各自的当前状态。

## ID 和访问对象

实体 ID 用于在牌桌中定位实体。通过牌桌的 `operator[]` 或玩家、角色的遍历接口得到的实体对象，是访问该实体的入口；复制这个对象仍访问同一个实体，不会复制一份游戏状态。要建立独立的模拟分支，应复制牌桌，并为分支配套保存执行器和随机源状态。

玩家 ID 只有 0 和 1。其他 ID 不表示“当前遍历到的第几项”。尤其是牌库顺序可以改变，而同一张牌的 [`deck_card_id`](deck_card_id.md) 不随换序改变。

## 只读访问

从只读牌桌取得的对象使用相应的 `*_view` 类型，只允许读取实体。可写实体对象可以隐式转换为只读视图。只将访问对象自身声明为 `const`，不会把它指向的实体变为只读。

## 移除与清理

`erase()` 使实体不再有效，默认遍历会跳过已移除实体。有些遍历接口的 `SkipErased = false` 可以连同尚未清理的已移除实体一起访问；这时须先检查 `is_valid()`，再读取定义、状态或 ID。

实体访问对象、状态引用和遍历范围不拥有牌桌。增加或移动同类实体可能使已取得的访问对象和引用失效；需要跨这些操作保存身份时保留 ID，并重新从牌桌取得访问对象。`clean_up()` 还可能改变 ID，所以不能跨清理保留这些 ID。不要把 `is_valid()` 当作悬空对象检查：它只适用于仍能安全访问的对象。

## 卡牌的移动

牌库位置 0 是底部，末尾是牌库顶。按位置操作牌库的接口使用当前顺序中的位置，区别于卡牌 ID。

`take_top_deck_card()`、`take_deck_cards()` 和 `take_hand_card()` 取出可搬运的 [`card_data`](card_data.md)，可交给同一牌桌的加牌或插牌接口。这样移动卡牌可以保留其附带状态。取出后原实体不再有效；搬运过程中不要清理牌桌，也不要把同一份附带状态的数据重复装入多个位置。

## 底层状态修改

直接设置状态、增加实体和调用 `erase()` 是牌桌操作；它们本身不执行完整的规则结算，也不广播规则事件。需要按对局规则进行抽牌、伤害、创建或销毁实体等操作时，应使用相应的[指令](../executor/instructions.md)。
