# draw_cards

从牌库抽取若干张手牌。

## 字段

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `count` | `std::uint32_t` | 请求抽取的牌数。 |
| `player` | `relative_player` | 相对执行时 `table.state().active_player` 的 `current` 或 `other`；默认为 `current`。 |

## 执行

本命令入口不要求额外栈输入。若有牌成功加入手牌，会临时压入 `hand_card_id[]`、游标和 `stage_t`，并逐次压入 `card_drawn` 广播 frame；彻底完成时恢复入口栈形状。

先解析实际玩家，再将其牌库顶至多 `count` 张牌依次移除并加入手牌，超过手牌上限的部分直接丢弃。然后，成功加入手牌的牌按照加入顺序，依次推进 [`card_drawn`](../events/card_drawn.md) 广播。

每张成功加入手牌的牌都会产生一次 `card_drawn` 广播。

## 注意

- 广播第一个 `card_drawn` 前，本批次的所有牌都已经离开牌库，能够进入手牌的牌也都已经进入手牌。因此，事件响应程序不会改变本批次原本要抽到的牌。
- 每个 `card_drawn` 的响应者列表都在该次广播开始时按当时 table 采样；前一张牌的响应若创建了新实体，该实体可以响应本批次后续通知，但不能改变已经完成的抽牌批次。
- 因超过手牌上限而直接丢弃的牌不广播 `card_drawn`，不触发“抽牌后”效果。
- 牌库为空时不抽取牌。手牌已满时仍从牌库移除至多 `count` 张牌，但它们都会直接丢弃。

## 形式化语义

1. 记执行前的牌库中牌数为 `N`，令 `X = min(count, N)`。
2. 令 `C` 为空序列。
3. 从牌库顶部开始依次处理 `X` 张牌：移除牌库顶部的一张牌；若当前手牌数量小于手牌上限，则将其加入手牌，并将其 `hand_card_id` 追加到 `C`；否则将其丢弃。
4. 对于每个 `c` ∈ `C`，依次推进 `card_drawn { card = c }` 广播。
